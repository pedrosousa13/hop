# Hop Launcher M1 — Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the cargo workspace with `hop-protocol` (typed IPC contract) and `hop-core` (query router, nucleo-based fuzzy ranking, learning engine, aliases, provider trait, search pipeline), with the old extension's JS test suites ported as the behavioral spec — all green.

**Architecture:** Pure-logic milestone: no daemon, no UI, no sockets. Two library crates whose tests encode the launcher's behavior. `hop-protocol` defines every type that will ever cross a process boundary; `hop-core` implements search behavior against those types. Later milestones (daemon M2, GTK M3) consume these crates unchanged.

**Tech Stack:** Rust stable (edition 2024), `serde`/`serde_json`, `nucleo-matcher` (fuzzy), `tokio` (traits only — `sync` + `time` features), `thiserror`, `tempfile` (dev).

**Reference sources (read-only inputs to this plan):**
- Spec: `docs/superpowers/specs/2026-07-30-hop-launcher-v1-design.md`
- Old extension (JS specs to port): `/home/pedro/apps/hop-launcher/lib/` and `/home/pedro/apps/hop-launcher/tests/`
- Rust branch salvage: `/home/pedro/.config/superpowers/worktrees/hop-launcher/feat/cross-linux-hopd-v1/crates/hopd/src/learning.rs`

## Global Constraints

- Rust stable, edition 2024; `cargo clippy --workspace --all-targets -- -D warnings` must pass at every commit.
- No disk reads, subprocess spawns, or network calls on any query path (spec §3). In M1 that means: `route()`, `rank()`, alias resolution, and learning boost lookup are pure in-memory functions; learning persistence happens only via explicit `load()`/`save()`.
- Every IPC-crossing type lives in `hop-protocol` with `#[serde(deny_unknown_fields)]` off (forward compat) and an explicit `API_VERSION`.
- Alias boost must always beat learning boost: alias boost constant 180.0, learning boost cap 85.0 (spec §4).
- Inferred query modes augment (non-exclusive); only explicit prefixes are exclusive (spec §4).
- Commit messages: conventional commits. No AI attribution and no `Co-Authored-By` trailer — this repo's landing rules forbid it.

```rust
// provider.rs
pub struct ProviderManifest {
    pub id: &'static str,
    pub kinds: Vec<Kind>,
    pub modes: Vec<Mode>,            // which routed modes this provider serves
    pub min_term_len: usize,         // pre-filter: skip if term shorter (0 = always run)
    pub budget: Duration,            // per-query deadline
}
pub struct QueryCtx { pub cancel: CancellationFlag, pub deadline: Instant }
#[derive(Clone, Default)]
pub struct CancellationFlag(Arc<AtomicBool>);   // fn is_cancelled(&self) -> bool; fn cancel(&self)
#[derive(Debug, thiserror::Error)]
pub enum ProviderError {
    #[error("provider timed out")] Timeout,
    #[error("provider cancelled")] Cancelled,
    #[error("{0}")] Failed(String),
}
// Native async fn in traits (Rust 2024) — no async_trait macro needed.
pub trait Provider: Send + Sync {
    fn manifest(&self) -> ProviderManifest;
    async fn query(&self, q: &RoutedQuery, ctx: &QueryCtx) -> Result<Vec<Item>, ProviderError>;
    async fn execute(&self, item_id: &ItemId, action_id: &ActionId) -> Result<ExecOutcome, ProviderError>;
}

// pipeline.rs
pub struct Pipeline { pub ranker: Ranker, pub aliases: Aliases, pub learning: Learning, pub weights: Weights }
impl Pipeline {
    /// Pure post-processing: given all provider items for a query, produce the final ordered list.
    /// Applies: mode filter (exclusive), alias effect, learning boosts, ranking, append_to_end pinning, max_results cap.
    pub fn assemble(&mut self, raw_query: &str, provider_items: Vec<Item>, max_results: usize) -> Vec<Item>;
}
```
Note: provider *scheduling* (parallelism, timeouts, streaming) is daemon work — M2. M1's pipeline is the pure assembly function both the daemon and tests share.
